# Plan: bring the C attitude UKF in line with the newer MATLAB version

## Reference and scope

The supplied MATLAB function is the specification. The copy at `../MATLAB/Algorithms/simulink.m` differs only in two output comments and a trailing newline. Its `iterate` and helper functions are therefore a local reference for the port. The C filter is in `src/iterate.c`; its public API is in `include/iterate.h`, with production calls in `src/body.c` and simulation calls in `src/test.c`.

Port the UKF mathematics and measurement modes into the reusable C filter. Put MATLAB's truth-state simulation, random sensor noise, mode timer, logging outputs, and fixed `dt = 0.1` in the C simulation test harness, since `body.c` receives real sensor readings and a caller-supplied `dt`. For production, select one or two vectors from actual Sun availability and gate vector corrections at the 0.1 Hz cadence. The MATLAB source comment that says the mode period is 6000 steps is stale: the executable expression `60 * 45 / 0.1` is **27,000 steps (45 minutes)**.

Conventions throughout: scalar-first Hamilton quaternions; `q_body_to_eci * v * inverse(q_body_to_eci)` rotates a body vector into ECI; the three gyro components are body-frame radians per second; the six filter states are `[attitude_error(3), gyro_bias(3)]`; matrix and sigma arrays are row-major in C. The C code already has six states and 13 sigma points, so there is no nine-to-six resize to perform.

## Public API and data contract

Change `include/iterate.h` to expose a status-returning `iterate` with the existing state, quaternion, covariance, gyro, `Q`, `dt`, and output buffers plus `vector_count` and `do_update`. On correction calls, `ref` and `body` each contain `3 * vector_count` **unit-vector** floats in magnetic-then-Sun order, and `R` is a row-major square matrix of that same dimension. On predict-only calls, `ref`, `body`, and `R` may be null and are not accessed. `Q` remains a row-major 6x6 covariance increment per propagation call. Keep the current `STATE_SIZE` and `NUM_SIGMAS` constants, but replace `MSMT_SIZE` with `MAX_MSMT_SIZE = 6` and an active runtime dimension. Initialize outputs only after every step succeeds.

The MATLAB top level initializes its nominal quaternion from the truth quaternion. Production has no truth quaternion: preserve QUEST initialization in `body.c`. The MATLAB top level also simulates a fixed bias and sensor noise; the production filter must estimate bias from the supplied raw gyro without injecting simulation noise or truth bias. Its `w_est`, error angle, bias-error, and mode outputs are test/logging quantities, not new filter outputs.

## Implementation sequence

1. Update `include/iterate.h` and all four call sites (`body.c` has two; `test.c` has two) so the changed API compiles.
2. Correct sigma scaling, covariance handling, Cholesky orientation, quaternion composition, and weighted mean in `src/iterate.c`.
3. Add the predict-only and 3-or-6-component correction paths, with checked matrix operations and status propagation.
4. Update `body.c` initialization, vector normalization, sunlight/eclipse routing, cadence, and bias-state persistence.
5. Replace the legacy test assumptions, add MATLAB fixture comparisons, then run the project build and test executable.

## Verification and acceptance criteria

- Build with `cmake -S adcs-unix-testing -B adcs-unix-testing/build` and `cmake --build adcs-unix-testing/build -j4`; run `adcs-unix-testing/build/adcs-test`. The current executable does not register CTest tests, so the revised test runner must return nonzero on a failed assertion.
- Compare deterministic C steps with MATLAB `iterate` using identical initial `x`, `q`, `P`, `Q`, `R`, gyro, vectors, and `dt`. Cover two-vector correction, one-vector correction, and predict-only propagation. Use sign-invariant quaternion angle error and explicit float32 tolerances; compare all six state values and all 36 covariance entries.
- Check sigma weights and reconstruction of a covariance with nonzero off-diagonal entries; check Cholesky failure handling and both input/output covariance repair, including a symmetric matrix with positive diagonal but a negative eigenvalue.
- Check noncommuting quaternion cases to expose multiplication-order errors; check that final propagated errors are measured against the final weighted mean.
- At `dt = 0.1`, verify updates occur at timesteps 0, 100, 200, ...; between them, only prediction runs and process noise accrues once per step. Verify a mode switch at timestep 27,000 with magnetic-only corrections after the switch in the simulation harness. For production, verify sunlight-to-eclipse and eclipse-to-sunlight transitions use actual sensor availability, not the simulation timer.
- Verify zero and non-finite reference or body vectors cannot reach normalization or matrix correction; a rejected update must not partly overwrite state outputs. Check that bias persists through prediction and eclipse, and that no caller subtracts bias before the UKF does.

## Known source ambiguities to resolve in the port

- The MATLAB comments still mention an old 6000-step mode period and an old scale-factor term. The executable MATLAB code uses 27,000 steps and no scale-factor state or truth term; use those executable values.
- MATLAB's `ensure_positive_definite` uses double-precision eigenvalues; the C build uses float32 CMSIS matrices. Match its symmetric shift rule as closely as float32 permits, and establish parity tolerances from deterministic fixtures.
- `body.c` receives a `dt` and sensor arrays but no separate sample-freshness flag. The proposed cadence assumes each `body()` call carries the current sensor sample. If that assumption is false, the input interface will need a freshness indication before a 0.1 Hz correction can be claimed to use a new reading.
